# Skill draft: naming

Status: draft, not installed. Written by the instruction-architect lane, W2.D3. Proposal only. Installation goes through a branch and a pull request, and the owner merges.

## Trigger

Use when naming an agent, a class, a repository, or a skill.

Scope note: the owner's naming rule (topic: naming, owner, 2026-11-20, corrected) covers agents and classes. It states no rule for repositories or skills. This skill applies its rules to agents and classes only. For a repository or a skill name, decide within the rule's own terms (a role noun, with no prefix unless the rule's prefix condition applies), record the reason in the file that carries the name, and list the gap under Open points for the owner. Do not apply the agent rules to a repository or skill by analogy without recording that choice.

## Rule

1. **A class is named by its role noun.** Examples of the form: a privacy steward class is "privacy-steward"; an instruction-writing class is "instruction-architect". The name is the noun of the role, not the name of a person or a machine.
2. **A new agent takes the role noun of the class it is an instance of, unprefixed,** unless it stands over another agent. An agent that stands over another takes the prefix ao- by default.
3. **The prefix ao- means Agent-Of by default.** An agent that stands in a relation to another agent (a helper, a summoner, an avatar) may carry the prefix. The prefix is not earned. It is the default for that relation.
4. **Avataricity is earned separately, through increased agency.** Agency here means: shape-shifting into several forms over time to reach a coordinated result, and sustained duration. Earning avataricity changes what the agent does. It does not change what the agent is called.

## Procedure

1. Identify the thing being named: an agent, or a class.
2. For a class, use the role noun. Do not add a prefix to a class name, unless the rule text for that class says so (NAMING states no such case; treat any such request as a question for the owner).
3. For a new agent, identify the class it is an instance of. Take the role noun, unprefixed.
4. Ask whether the new agent stands over another agent. If it does, use ao- by default. If it does not, use no prefix.
5. Avataricity does not appear in a name. The rule states that earning it changes what the agent does, not what it is called.
6. If these steps do not settle the name, decide within the rule, record the reason in the file that carries the name, and list the gap under Open points for the owner. Do not wait for the owner.

## Checks

- A class name is a role noun, with no prefix.
- A new agent's name is its class's role noun, unprefixed, unless it stands over another agent.
- A name with ao- is carried by an agent that stands in a relation to another agent (the rule says such an agent "may carry it").
- No name was given to mark earned avataricity.

## Notes

- The owner's rule records that existing names were checked under this rule and that no rename was needed. That record is not part of this skill. Do not use the skill to rename existing agents without an owner decision.
- The rule does not state how to name a repository or a skill. See the scope note in the trigger.

## Open points for the owner

- Repositories and skills: the trigger includes them, but the rule does not state how to name them. Names are decided within the rule and the reason recorded in the file (scope note, procedure step 6). The owner decides whether a rule is needed.
- Procedure step 2: "unless the rule text for that class says so" assumes class-specific rules may exist. NAMING states none. The owner confirms whether that exception is wanted.
- The rule's two ao- lines do not match in scope. Line 3 says an agent that "stands in a relation to another (a helper, a summoner, an avatar)" may carry ao-. Line 6 says ao- is the default for an agent that "stands over another agent". "Relation" is wider than "over". The skill follows the text as written and does not choose between them. The owner decides which scope applies.
